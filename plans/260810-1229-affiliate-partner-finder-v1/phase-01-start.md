# Phase 1: Scaffold, Manifest, Types & Config

## Overview
Stand up a WXT + TypeScript MV3 project with the correct manifest permissions,
the typed data schema, and the isolated detector config (keywords/platforms/paths).
No runtime logic yet — this is the skeleton everything else builds on.

## Requirements
- Functional: `wxt dev` loads an (empty-but-valid) MV3 extension in Chrome; `wxt build` succeeds.
- Non-functional: config isolated in `lib/config.ts` (NFR-05); types cover full schema (`docs/06`).

## Architecture
WXT convention (`docs/11-tech-stack.md`): entrypoints for `background` + `popup`;
shared logic in `lib/`. Manifest generated by `wxt.config.ts` — permissions and
host_permissions come from `docs/04` §5 and `docs/09`.

## Related Code Files
- Create: `package.json` — deps: `wxt`, `typescript`, `idb`, `vitest`; scripts: `dev`, `build`, `zip`, `test`, `compile` (`tsc --noEmit`).
- Create: `wxt.config.ts` — manifest: name, version `1.0.0`, `permissions:["tabs","scripting","storage","alarms"]`, `host_permissions:["*://*.trustpilot.com/*","<all_urls>"]`.
- Create: `tsconfig.json` — extends `.wxt/tsconfig.json`, strict true.
- Create: `lib/types.ts` — `Company`, `ScanResult`, `Evidence`, `LinkHit`, `PathHit`, `Verdict` (`'affiliate'|'partner_trade'|'none'|'unknown'`), `Confidence` (`'high'|'medium'|'low'|'blocked'`), `LoadStatus` (`'ok'|'blocked'|'timeout'|'error'`), `Job`/`JobState`, `AppConfig`. Mirror `docs/06`.
- Create: `lib/config.ts` — `CONFIG` object: `strong[]`, `weak[]`, `platforms[]`, `paths[]` copied verbatim from `docs/05` §2–4; `detectorVersion="1.0.0"`; defaults `{delayMs:2000, maxRetries:2, tabTimeoutMs:20000}`.
- Create: `entrypoints/background.ts` — stub (empty listener), fleshed in P3.
- Create: `entrypoints/popup/index.html` + `main.ts` + `style.css` — stub shell, fleshed in P4.
- Create: `.nvmrc` (18+), README note for "load unpacked".

## Implementation Steps
1. `npm init` + install WXT/TS/idb/vitest; add scripts.
2. Write `wxt.config.ts` with manifest fields above; run `wxt prepare`.
3. Author `lib/types.ts` from `docs/06` schema (exact field names: `finalUrl`, `loadStatus`, `verdict`, `confidence`, `evidence.linkHits/platformHits/pathHits/junkBaselineStatus`, `scannedAt`, `detectorVersion`).
4. Author `lib/config.ts` — verbatim keyword/platform/path lists from `docs/05`; keep as plain exported arrays (extensible per NFR-05).
5. Add stub background + popup entrypoints so `wxt build` passes.
6. `npx tsc --noEmit` clean; `wxt build` produces `.output/chrome-mv3`.

## Success Criteria
- [x] `wxt build` succeeds; `.output/chrome-mv3/manifest.json` has exact permissions/host_permissions above.
- [x] `tsc --noEmit` passes with strict mode.
- [x] `lib/config.ts` arrays match `docs/05` §2–4 exactly (no omissions).
- [x] `lib/types.ts` field names match `docs/06` exactly.

## Risk Assessment
- Node 24 vs WXT: WXT supports current Node; if a peer warning appears, pin via `.nvmrc` — non-blocking.
- Manifest `<all_urls>` triggers a broad-permission warning on install — expected and documented (needed to scan arbitrary target sites, `docs/04` §5).
